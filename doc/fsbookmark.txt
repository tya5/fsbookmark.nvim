1. INTRODUCTION                                      *fsbookmark-introduction*

fsbookmark.nvim bookmarks files and directories together with a description
and free-form labels, and makes all of it fuzzy-searchable from one picker.

Requires Neovim >= 0.10. The picker needs one of snacks.nvim (with `picker`
enabled), telescope.nvim or fzf-lua; whichever is installed is used, in that
order. The API works without any of them.

==============================================================================
2. SETUP                                                    *fsbookmark-setup*

>lua
    require("fsbookmark").setup({})
<
Defaults: >lua
    {
      dir = nil,       -- stdpath("data")/fsbookmark/bookmarks
      workspace = { enabled = true },
      shared = { enabled = true, file = ".fsbookmark.json" },
      autosave = true,
      watch = true,
      icons = {
        bookmark = "★", broken = "⚠",
        global = "🌍", workspace = "📁", shared = "👥",
      },
      picker = {
        backend = "auto",  -- "snacks" | "telescope" | "fzf-lua"
        keys = {
          edit = "<c-e>", delete = "<c-x>", reload = "<c-l>",
          yank = "<c-y>", reveal = "<c-o>", share = "<c-h>",
        },
      },
      -- `m` is explorer_move in the snacks explorer; use "b" there.
      explorer = { enabled = true, key = "mb" },
      keys = { enabled = true, prefix = "<leader>m" },
      open_directory = nil,
    }
<
The keymap prefix is `<leader>m` rather than `<leader>b` because LazyVim uses
`<leader>b` for its buffer group.

3. COMMANDS                                              *fsbookmark-commands*

                                                                *:FSBookmark*
:FSBookmark [subcommand] [path]

    add     [path]   Register a path (default: current buffer).
    remove  [path]   Unregister a path.
    toggle  [path]   Add if missing, remove if present.
    edit    [path]   Prompt for description and labels.
    share   [path]   Move a bookmark into the repository's shared file.
    unshare [path]   Move it back out into your personal files.
    list             Open the picker. This is the default subcommand.
    prune            Remove every bookmark whose path no longer exists.
    save             Write to disk.
    load             Re-read from disk, discarding unsaved changes.

==============================================================================
4. MAPPINGS                                              *fsbookmark-mappings*

Registered when `keys.enabled` is true, under `keys.prefix` (`<leader>m`):

    a    Add bookmark
    f    Find bookmarks
    t    Toggle bookmark
    e    Edit bookmark
    r    Remove bookmark

In explorer buffers (snacks explorer, neo-tree, oil), `explorer.key` (`mb`)
toggles the bookmark for the path under the cursor.

5. PICKER                                                  *fsbookmark-picker*

>lua
    require("fsbookmark").picker()
<
    <CR>     Open (directories open in the explorer)
    <C-e>    Edit description and labels
    <C-x>    Delete (respects multi-selection)
    <C-l>    Reload from disk
    <C-y>    Copy path
    <C-o>    Reveal in explorer
    <C-h>    Share / unshare (see |fsbookmark-shared|)

telescope and fzf-lua support <C-e>, <C-x> and <C-y>. Pin a backend with
`picker = { backend = "telescope" }`.

<C-d> and <C-r> are not used: snacks binds those (and most other <C-*> keys)
inside the picker, and reusing one shadows its action.

The picker is a `live` snacks source: the prompt goes to this plugin's parser
(see |fsbookmark-search|), not to the built-in matcher, so `label:` filters
behave identically in the picker and in |fsbookmark.search()|.

To expose it as `Snacks.picker.fsbookmark()`, register the source as a table
(snacks walks `sources` on setup, so a bare function raises): >lua
    sources = {
      fsbookmark = {
        config = function(opts)
          return require("fsbookmark.picker").source(opts)
        end,
      },
    }
<

6. SEARCH                                                  *fsbookmark-search*

Path, description and labels are fuzzy-matched. Multiple terms are ANDed. >
    runtime
    runtime hot
    label:core
    label:core label:ssd
    label:core scheduler
    scope:workspace
    scope:shared
<
The path is fuzzy-matched on its basename and substring-matched on the full
path. `label:` filters are ANDed; multiple `scope:` filters are ORed.

7. API                                                        *fsbookmark-api*

`path` defaults to the current buffer and is normalized before use.

fsbookmark.add({path}, {fields})                            *fsbookmark.add()*
    Register a path. {fields} may hold `description` and `labels`.
    Returns the bookmark and whether it was newly created.

fsbookmark.remove({path})                                *fsbookmark.remove()*
    Unregister a path. Returns the removed bookmark or nil.

fsbookmark.toggle({path})                                *fsbookmark.toggle()*
    Returns true when the bookmark now exists.

fsbookmark.get({path})                                      *fsbookmark.get()*
fsbookmark.list()                                          *fsbookmark.list()*
fsbookmark.search({query})                               *fsbookmark.search()*
fsbookmark.update({path}, {data})                        *fsbookmark.update()*
fsbookmark.labels()                                      *fsbookmark.labels()*
fsbookmark.workspace()                     see |fsbookmark-workspace|
fsbookmark.share({path})                      see |fsbookmark-shared|
fsbookmark.unshare({path})                    see |fsbookmark-shared|
fsbookmark.is_broken({bookmark})                      *fsbookmark.is_broken()*
fsbookmark.open({bookmark})                                *fsbookmark.open()*
fsbookmark.edit({path}, {on_done})                         *fsbookmark.edit()*
fsbookmark.picker({opts})                                *fsbookmark.picker()*
fsbookmark.save()                                          *fsbookmark.save()*
fsbookmark.load()                                          *fsbookmark.load()*

A bookmark is: >lua
    {
      id = "...",
      path = "/abs/path",
      type = "file"|"directory",
      description = "",
      labels = { "core" },
      scope = "global",  -- or "workspace" / "shared"
      source = "manual",
      metadata = {},
      created_at = 0,
      updated_at = 0,
    }
<
`scope` and `source` are reserved: the first for the planned per-workspace
split, the second for future git/lsp/recent providers. Both are written from
the start so that growing into them needs no migration, and both are always
"global"/"manual" today. `metadata` is a free-form table for other plugins and
for fields added later; `description` and `labels` stay top level so the
public shape does not break.

Older files missing any of these fields load fine — the defaults are applied
on read.

9. STORAGE                                                *fsbookmark-storage*

>
    stdpath("data")/fsbookmark/bookmarks/
        global.json
        workspace/
            reyn-3f8a1c9e2b04.json
<
>json
    { "version": 1, "root": "...", "name": "reyn", "bookmarks": [ ... ] }
<
Written atomically. A corrupt file is reported and treated as empty; it is not
overwritten until something changes.

An older `fsbookmark/bookmarks.json` is moved to `bookmarks/global.json` on
first load.

Bookmarks pointing at a missing path are shown as broken (`⚠`) rather than
deleted. Renames done inside Neovim are followed. `:FSBookmark prune` removes
all broken bookmarks.

10. WORKSPACE                                           *fsbookmark-workspace*

A workspace is the project currently open. It is resolved automatically and
does not appear in the public API: there is no workspace list, switcher,
creation or deletion, and no session management.

Resolution order:

    1. LSP workspace root
    2. Nearest ancestor containing `.git`
    3. Current working directory

It decides one thing — which file a bookmark is written to. Paths under the
root go to the workspace file, everything else to `global.json`. Reads always
merge global with the current workspace, so other projects' bookmarks stay
hidden.

`scope` is derived from the file a bookmark was read from. It is never
written to disk and never set by a caller. Renaming a file across the root
boundary moves it between files.

fsbookmark.workspace()                                *fsbookmark.workspace()*
    Returns the current root and name, or nil. Informational only.

Disable with: >lua
    require("fsbookmark").setup({ workspace = { enabled = false } })
<
==============================================================================
11. SHARED BOOKMARKS                                       *fsbookmark-shared*

A repository can ship its own bookmarks in a checked-in file at the workspace
root (`.fsbookmark.json` by default). It is read automatically and merged in,
and shown with the "shared" icon.

Paths there are stored relative to the repository root, so the file means the
same thing on every machine. The machine-specific root is not written.

Nothing is written to it implicitly. A bookmark moves in only via: >
    :FSBookmark share
    :FSBookmark unshare
<
or <C-h> in the picker, which toggles between the two. A personal note can
therefore never end up in a commit by accident.

Disable with: >lua
    require("fsbookmark").setup({ shared = { enabled = false } })
<
==============================================================================
12. EXPLORER                                             *fsbookmark-explorer*

>lua
    require("fsbookmark.explorer").toggle()
<
Reads the cursor path from the snacks explorer, neo-tree or oil, falling back
to the current buffer.

`require("fsbookmark.explorer").format(item, picker)` is a drop-in `format`
for the snacks explorer source that prefixes bookmarked entries with the
bookmark icon.
